작업물

career-prep

취업 준비의 반복 작업을 Claude Code 스킬로 만든 툴킷

왜 만들었나
여러 단계를 거치거나 되풀이되는 작업은 스킬로 만들어 씁니다. 회사·직무 조사와 제 저장소에서 소재를 뽑는 일이 그런 작업이었습니다.
어떻게 확인했나
조사 스킬은 채용 공고 한 장에서 출발하고 문장마다 출처를 답니다. 이 스킬로 친구의 면접 예상 질문을 뽑아 줬습니다. 친구가 1차 기술 면접에서 실제로 들은 질문이 그 목록에 들어 있었습니다.

claude-skills

직접 만들어 쓰는 Claude Code 스킬과 output-style 모음

왜 만들었나
처음에는 공식 skill-creator처럼 규칙을 적고 eval을 통과할 때까지 고쳤습니다. 그러자 스킬이 eval에 과적합했습니다. 그래서 규칙 대신 이 일을 왜 하고 어떤 순서로 하는지를 적는 쪽으로 바꿨습니다.
어떻게 확인했나
Claude Code의 답은 길었습니다. 답 안에서 사실과 짐작이 구분되지 않았습니다. 그래서 output-style layered를 만들어 첫 문장이 답이 되게 했습니다. 판단 앞에 [확인]/[추정]/[감] 표시를 붙이는 규칙은 스타일을 바꿔도 남도록 CLAUDE.md로 옮겼습니다.

md-holon

새 글이 이미 쌓인 글과 부딪히는 자리를 기록해 사람이 정하게 하는 저장소

왜 만들었나
첫 시도에서는 기획을 크게 잡았습니다. 애매한 부분을 AI에 맡겼다가 판단 기준을 잃었습니다. 그래서 글 세 편으로 작게 다시 시작했습니다. 자동화하기 전에 결과물을 손으로 먼저 썼습니다.
어떻게 확인했나
LLM이 낸 판정마다 근거가 되는 원문 인용을 붙이게 했습니다. 인용이 원문에 글자 그대로 있는지는 스크립트가 검사합니다. 앞서 쌓인 글과의 비교가 빠졌는지도 스크립트가 검사합니다. 2026-09-30에 돌린 검사 기준으로 글 세 편 사이에 부딪힘 세 건이 기록돼 있습니다. 그중 한 건은 아직 편을 정하지 않은 채 열려 있습니다.

resume

만든 것 대신 판단을 묻는 이력서 양식과 yaml→HTML·PDF 도구

왜 만들었나
AI를 쓰면 만든 것 자체는 흔해집니다. 그래서 증거의 무게가 만든 것에서 판단으로 옮겨 간다고 봤습니다. 이 양식은 무엇을 옳음으로 봤나, 무엇을 맡겼나, 어떻게 확인했나, 무엇을 버렸나를 묻습니다.
지금 상태
yaml 한 파일을 고치면 HTML과 PDF가 나옵니다. main에 push하면 GitHub Actions가 빌드해 GitHub Pages에 올립니다.
